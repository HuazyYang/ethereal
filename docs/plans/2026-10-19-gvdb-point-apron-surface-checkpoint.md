# M5 point support, apron overrides and owned surface checkpoint

Status: implemented and validated on Windows, 2026-10-19. The mega project remains in progress.

Samples `750d7cb` adds optional FloatSupport topology coverage. The original 32-byte descriptor prefix, IID, vtable and default Legacy behavior remain compatible. Current 40-byte descriptors opt into binary32 `p-radius` / `(p+1)+radius` endpoints, floored onto the leaf grid. Accumulation follows the existing root phase; full rebuild uses phase zero. Actual containing leaves, center-first order, pre-deduplication visit budgets, stable append IDs and failed-preparation rollback are preserved. See the [point contract](../../ethereal-samples/src/gvdb_samples/gvdb/GVDBNvrhiPointApi.md).

Samples `a8105e1` adds a separate public apron operator and a concrete core overload. Each call may override selected channels' missing-neighbor values without changing channel descriptors or new-interior initialization. All five formats preserve interior bytes and existing neighboring values; old snapshots remain intact, and unused storage is zero. Override values follow channel void-value storage rules and are validated/copied before no-op handling. Existing voxel IIDs/vtables and mutation artifacts remain unchanged. See the [apron contract](../../ethereal-samples/src/gvdb_samples/gvdb/GVDBNvrhiApronApi.md).

Samples `f643cab` adds raw colored level-set rendering from one retained public snapshot and viewer metadata/overlay hooks. There is no duplicate atlas or packed topology. Strict artifact validation precedes rendering; optional RGBA8 color, explicit scalar background, empty publications and resource lifetimes are covered. Existing viewer scenes retain their behavior. Snapshot-only scenes currently support custom volume/surface rendering and overlays; voxel/section/inset fallback still requires the legacy volume representation. See the [surface helper contract](../../ethereal-samples/src/gvdb_samples/samples/sample-utils/OwnedVolumeSurface.md).

## Next integration

Point-fusion now has the required topology support policy, separate support/distance radii, apron override and raw colored surface renderer. Its migration will preserve scanner/compaction behavior and use explicit PointSet conversion, topology accumulation, gather and apron publication. Topology/gather/apron remain separate atomic operations; the application retains the previous visible snapshot until the sequence succeeds. No full-frame owner rollback is claimed.

Dense regional downsampling remains the next public query adapter: two transformed box endpoints, inclusive X-fast Float32 sums and explicit caller completion with CPU final division. Scatter, voxelization, weighted ushort gathering, other consumer ownership, Linux, real multi-GPU transfer, broader interactive/reference/performance acceptance and reference retirement remain open.
