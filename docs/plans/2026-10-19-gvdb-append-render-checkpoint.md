# M5 stable-ID accumulation and first owned renderer checkpoint

Status: implemented and validated on Windows, 2026-10-19. The mega project remains in progress.

Samples `ca793cc` adds an opaque authenticated accumulation candidate. It clones the finished host, captures owner/host/channel/publication identity, and validates old node/child-list prefixes before accepting an appended graph. Existing IDs keep the same epoch; active leaves cannot disappear, inactive leaves can reactivate, and the old root can gain new ancestors. Clear/reconfigure, reordered/moved nodes, changed old links or semantic metadata, and stale/foreign candidates fail without changing the live host or output. Preparation deep-copies again, so later candidate edits/destruction cannot affect a prepared generation. Publication preserves channel interiors and metadata, swaps within the stable host object, and invalidates raw pool borrows. Full rebuild remains a separate epoch-changing operation. The append path is topology-only and requires preservation enabled with no channel uploads.

Samples `b2f1185` moves `render-to-file` to the public volume/serializer/snapshot path. The application releases its owner after loading and renders from a retained snapshot. A small app-level helper binds raw atlas and topology ranges directly; no second scalar atlas/topology owner is constructed. The raw shader wrapper shares the existing raycast equations. Empty snapshots return background and infinite depth. The helper validates formats/ranges/dispatch dimensions before allocation and refreshes every binding from one snapshot. Production remap/raycast artifacts are built independently of test targets. Existing camera, transfer function, surface/volume equations and PNG conversion are preserved. Tiny steps that overflow the supported march count now fail explicitly before conversion to uint32.
